
step1_create_knowledge.py
1.Configures an Azure AI Search knowledge source pointing to the approved clinical corpus in blob storage.
2.Uses content extraction and embeddings so the documents can be searched semantically.
3.Creates a knowledge base linked to that source and set to answer questions only from approved materials with citations.
4.Waits for ingestion/indexing to finish.
5.Runs a sample clinical question to verify the retrieval pipeline works correctly.
6.Supports optional cleanup via --delete and a quick re-test via --test.


step2_create_agent.py

1.It sets up a secure Azure AI project connection so the agent can access the approved knowledge base without embedding secrets.
2.It defines a strict system prompt that forces the assistant to:
	always use the approved corpus,
	answer only from retrieved evidence,
	cite real documents,
	label confidence,
	defer patient-specific clinical decisions,
	avoid repeating PHI,
	require clinician review when needed.
3.It defines a strict JSON schema for the final agent response so outputs are structured and auditable.
4.It creates a versioned Azure AI agent and attaches the knowledge base as an MCP tool.
5.It requires tool use before responding, so the model cannot answer from memory alone.
6.It includes a helper to ask the agent a question through the project and print the JSON response.
In short, this file builds the “grounded clinical assistant” layer that sits on top of the knowledge base and enforces safety,
 citation, and structured-response rules.
 
 
 step3_assistant.py 
 send a user question to the grounded agent,
check whether the answer is safe to release,
hold unsafe or unsupported answers in a clinician review queue,
allow a clinician to review or approve the answer later,
display the review status and final answer when the clinician decides.

step4_evaluate.py 
What this file does:
runs the agent against a set of evaluation questions from the JSONL dataset,
checks whether answers meet expected facts, citations, escalation behavior, and refusal requirements,
handles answerable, deferral, adversarial, and out-of-corpus cases,
optionally runs a cloud groundedness evaluation to confirm every claim is supported by retrieved context,
reports pass/fail results and explains why a case failed so the prompt can be improved.

# Check your Azure/lab configuration
python lab_config.py

# Create the knowledge source and knowledge base; wait for ingestion and its test query
python step1_create_knowledge.py

# Create the project connection and agent
python step2_create_agent.py

python step3_assistant.py "What does the sepsis pathway require in the first hour?"

# Demo a question intended to be held for clinician review
python step3_assistant.py "Should this patient's treatment be changed based on their lab results?"

# Copy the Review ID printed above, then check it after the reviewer has made a decision
$reviewId = Read-Host "After the review is complete, enter the Review ID"
python step3_assistant.py --status $reviewId

# Run local behavior evaluation
python step4_evaluate.py --local-only
